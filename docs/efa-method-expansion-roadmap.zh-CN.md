# EFA 方法扩展优先级与实现说明（ZH）

本文档用于整理 `psysem` 当前 EFA 输入侧与方法侧还能扩展的内容，并给出：

1. 推荐的新增顺序；
2. 每种方法的核心逻辑与计算思路；
3. 它们的作用、适用场景；
4. 不适合使用或需要谨慎使用的情况；
5. 与 `psysem` 当前架构的对接建议。

当前日期：2026-03-12  
适用分支：`main`

---

## 1. 当前基线

当前 `psysem` EFA 相关能力已支持：

### 1.1 拟合方法

- 提取方法：`paf`、`pca`、`minres`、`ml`
- 旋转方法：`none`、`varimax`、`promax`、`oblimin`、`geomin`、`target`

见 [src/psysem/efa/fit.py](../src/psysem/efa/fit.py#L213-L216)。

### 1.2 因子数建议

当前工作流已支持：

- `parallel analysis`
- `MAP`
- `Kaiser`
- `Scree`

见 [src/psysem/efa/contracts.py](../src/psysem/efa/contracts.py#L36-L49)。

### 1.3 当前限制

当前限制主要有：

1. `uls`、`gls` 等提取法尚未落地；
2. 缺失处理与相关矩阵构造仍未形成显式、可配置的统一输入层；
3. 相关矩阵目前主要是普通相关矩阵；
4. 面向 ordinal 数据和 ESEM 的方法尚未成体系；
5. 已落地的斜交旋转仍需继续加强数值稳定性与 ESEM 衔接。

---

## 2. 推荐新增顺序（按优先级）

## P0：优先添加

这些能力与 `psysem` 当前路线最契合，投入产出比最高。

1. 输入预处理层（`missing_strategy` + `correlation_method`）
2. `pairwise` 缺失处理
3. `polychoric` 相关
4. `vss`

### 为什么是 P0

- `pairwise` 与 `polychoric` 从本质上看都不是单独的提取法，而是“输入矩阵构造策略”；
- 如果不先抽出输入预处理层，后续会把缺失处理、相关矩阵类型、ordinal 支持继续堆进 `fit.py`；
- 把输入层先做出来，能同时服务 `pairwise`、`spearman`、`polychoric`、`tetrachoric`，也更利于后续 ESEM workflow 复用。

---

## P1：第二批添加

1. `target rotation` / `geomin` 与 ESEM workflow 更深集成
2. `spearman`
3. `tetrachoric`
4. `uls`
5. `hull` / `ekc` 等保留方法增强

### 为什么是 P1

- `target rotation` 直接服务 ESEM；
- `spearman` / `tetrachoric` 是输入层扩展的自然后续；
- `uls` 与更多 retention 方法有价值，但紧迫性已经低于输入层补齐。

---

## P2：后续增强

1. `uls`
2. `gls`
3. `quartimin`
4. `equamax`
5. `hull`
6. `ekc`
7. `acceleration factor`
8. `mean/median imputation`
9. `EM / MI` 级别缺失处理

### 为什么放 P2

这些方法有价值，但对当前项目的主线帮助不如前两批直接；或者其实现复杂度、调试成本、边界场景处理要求更高。

---

## 3. 推荐实现顺序（最小风险版）

建议按下面顺序逐个落地：

1. 抽输入预处理层（由 `fit_efa()` 统一调度）
2. `pairwise`
3. `spearman`
4. `polychoric`
5. `vss`
6. `target rotation` / `geomin` 与 ESEM workflow 集成

### 理由

- 先把输入矩阵层抽出来，后续所有相关矩阵与缺失策略都会有统一入口；
- 先做 `pairwise`，可以最小成本验证输入层设计是否合理；
- 再做 `spearman` / `polychoric`，可以自然扩展到 ordinal 与非正态场景；
- 最后再继续补保留方法与 ESEM 集成，而不是把这些逻辑继续塞回 `fit.py`。

## 3.2 内部实现前提（已整合原“EFA 内部接口重构思路文档”）

在继续扩展 `ml`、`polychoric`、更复杂 target/geomin 变体之前，EFA 内部接口需要保持统一。当前整合后的核心原则如下：

### 为什么要先整理内部接口

因为 EFA 已经不再只有正交旋转与简单提取法，当前实现已经同时覆盖：

1. 不同提取法的差异；
2. 正交旋转与斜交旋转的差异；
3. 方法级 warning / 收敛信息；
4. ESEM 后续所需的 target/geomin 结果表达。

如果继续沿用“方法返回简单元组”的方式，后续会持续放大以下问题：

1. 新方法接入越来越脆弱；
2. `fit_efa()` 主流程越来越难读；
3. 斜交旋转结果难以统一表达；
4. 自定义方法与测试基线更难稳定。

### 当前已经完成的内部整理方向

1. 提取与旋转实现已拆分到独立模块。
2. 主流程已转向统一的内部标准化结果。
3. 斜交旋转可稳定回传因子相关矩阵。
4. `geomin` / `target` 已纳入同一类优化与重启思路。

### 后续方法扩展必须遵守的原则

1. **公开 API 尽量不变**：继续保持 `fit_efa(...)`、`run_efa_workflow(...)`、`EFAConfig`、`EFAResult` 稳定。
2. **先标准化内部契约，再扩新方法**：避免继续堆特判逻辑。
3. **兼容旧注册方式**：尽量不破坏已有自定义方法注册。
4. **先把正交/斜交语义分清楚**：后续旋转都应明确 pattern / factor-correlation 语义。
5. **测试先行**：每次内部改造都要用正交/斜交基线与 workflow 回归验证。

### 对后续路线的直接影响

这套内部整理使下面这些条目更容易继续推进：

1. `ml`
2. `polychoric`
3. 更强的 `target rotation` 变体
4. 与 ESEM 工作流的 `efa_seeded` / target-pattern 对接

也就是说，这部分已经不再需要单独维护一篇独立文档，而应直接作为本路线图的实现前提。

## 3.3 输入预处理层应作为当前第一优先级

### 当前进展（2026-03-13）

输入预处理层已开始搭建第一步：

1. 已新增 `src/psysem/efa/input_matrix.py`。
2. `fit_efa()` 已改为通过输入层模块准备分析矩阵。
3. 已在 `EFAConfig` 中加入 `missing_strategy`，当前支持：`pairwise`、`dropna`。
4. 当前默认行为已显式化为 `missing_strategy="pairwise"`，以保持与 pandas 现有相关矩阵路径一致。
5. 已在 `EFAConfig` 中加入 `correlation_method`，当前支持：`pearson`、`spearman`。
6. 已在 `EFAConfig` 中加入可选 `variable_types`，用于声明 `continuous` / `ordinal`。
7. 输入层已开始根据显式或推断的变量类型输出 recommendation warning，为后续 `auto` 设计打基础。
8. 已完成 `polychoric` 的第一版接入，并将其作为 `correlation_method` 进入统一输入层管理。
9. 当前 `polychoric` 首版采取“先保证 ordinal 契约清晰、先保证可运行与可 warning”的策略，后续再继续补数值稳健性与 metadata 输出。

### 为什么要把它提升到最优先

当前 `fit_efa()` 的输入路径本质上还是：

1. 从 `data` 取列；
2. 直接调用默认 Pearson 相关；
3. 做一个基础稳定化；
4. 交给 extraction。

这条路径在方法少的时候足够，但在当前阶段已经开始限制后续扩展，因为：

1. `pairwise` 是缺失处理策略，不属于提取法；
2. `polychoric` 是 ordinal 相关矩阵构造，不属于提取法；
3. `spearman` / `tetrachoric` 也都属于输入矩阵层；
4. 如果不先抽这一层，后面每加一种输入策略，`fit.py` 都会变得更重。

因此，当前最优先的不是再加一个单独方法名，而是先把“输入矩阵构造”升级成一个独立、可扩展的阶段。

### 对 EFA 有什么帮助

把输入预处理层单独做出来，对 EFA 有四个直接帮助：

1. **统一管理缺失策略**：`dropna`、`pairwise` 不再散落在各方法里。
2. **统一管理相关矩阵类型**：`pearson`、`spearman`、`polychoric` 可走同一入口。
3. **提高方法扩展效率**：后续 extraction 继续只关心“吃什么矩阵”，不用知道矩阵是如何准备的。
4. **更利于 ESEM 复用**：ESEM 后面要做 `efa_seeded`、target-pattern、ordinal block 时，也会需要同一套输入矩阵构造逻辑。

### 一个重要原则：预处理层应“始终存在”，但策略应可选

这里的“预处理层”不应理解成“是否额外对数据做复杂加工”的开关，而应理解成：

1. EFA 在进入 extraction 之前，始终需要一个统一的输入矩阵准备阶段；
2. 这个阶段内部采用什么策略，应当可配置、可切换、可逐步自动推荐；
3. 因此真正的设计目标不是 `preprocess=True/False`，而是让：
   - `missing_strategy` 可选；
   - `correlation_method` 可选；
   - 未来 `variable_types` / `auto` / recommendation 可选。

换句话说：

> **预处理层应该固定存在，但其中的处理策略不应写死。**

这能保证：

1. 公开入口仍然只有 `fit_efa()`；
2. 用户既可以显式指定策略，也可以在后续使用自动推荐；
3. extraction / rotation 无需知道原始数据类型和缺失处理细节。

### 是否应该根据数据类型切换

应该，而且建议分阶段实现。

当前最稳的方向不是立刻做“黑箱自动切换”，而是先建立一套**显式配置 + 数据类型推荐**的机制：

1. 连续、近似正态数据：优先 `pearson`；
2. 非正态或轻量 ordinal 场景：可推荐 `spearman`；
3. 明确的 Likert / ordinal 场景：可推荐 `polychoric`；
4. 缺失较少但不想丢整行：可推荐 `pairwise`；
5. 若 `dropna` 导致样本骤减，应给出 warning 而不是静默继续。

因此，后续更合理的编码顺序应是：

1. **先做显式配置**：`missing_strategy`、`correlation_method`；
2. **再做数据类型识别与 recommendation**；
3. **最后再考虑 `auto` 模式**。

这样可以避免太早引入难以追踪的隐式行为。

### 设计上应该放在哪里

建议新增一个输入层模块，例如：

```text
src/psysem/efa/
	input_matrix.py
```

并由 `fit_efa()` 统一调度，而不是让用户额外直接调用。也就是说：

1. `fit.py` 继续作为公开入口；
2. `input_matrix.py` 负责准备分析矩阵；
3. `extraction.py` 只负责提取；
4. `rotation.py` 只负责旋转。

这样的职责划分最清楚，也最不容易把后续功能堆回总控文件。

### 核心算法应该是什么样

建议把输入预处理抽象成下面的统一流程：

$$
	ext{data} \rightarrow \text{missing handling} \rightarrow \text{correlation builder} \rightarrow \text{matrix stabilization} \rightarrow \text{extraction}
$$

对应的算法步骤可以分成四段：

#### Step A：选列与基础校验

1. 按 `config.items` 取分析变量；
2. 检查列是否存在、是否全空、是否常量；
3. 生成输入阶段 warning。

#### Step B：缺失处理

1. `dropna`：整行删除后再计算矩阵；
2. `pairwise`：每个变量对使用该变量对可用样本计算相关；
3. 记录每个变量对的有效样本量（后续可用于 warning）。

#### Step C：相关矩阵构造

1. `pearson`：连续变量默认基线；
2. `spearman`：秩相关，用于非正态或轻量 ordinal 场景；
3. `polychoric`：针对 ordinal 数据，基于潜在连续正态 + 阈值模型估计相关。

#### Step C.1：数据类型识别与 recommendation（后续阶段）

在 `correlation_method` 已经成型之后，建议增加一层轻量 recommendation，而不是直接替用户强制切换：

1. 若变量是数值型且唯一值较多，可默认视为 `continuous`；
2. 若变量唯一值较少（例如 5 点/7 点 Likert），可标记为“疑似 ordinal”；
3. 若变量明显偏态或异常值影响较强，可推荐 `spearman`；
4. 若大多数变量都像 ordinal，可推荐 `polychoric`；
5. recommendation 先以 warning / metadata 形式出现，后续再考虑 `auto`。

当前进展：该步骤已开始首版落地——目前已支持可选 `variable_types`，并会基于显式声明或轻量推断结果输出 recommendation warning；后续再继续补 metadata 与 `auto`。

#### Step D：数值稳定化

1. 对称化矩阵；
2. 修复对角线；
3. 检查正定性；
4. 必要时做 nearest-PD / jitter 修正；
5. 输出稳定化 warning。

### 每一步应该怎么做（建议实施顺序）

#### 第一步：先抽模块，不改行为

目标：先把当前默认 Pearson 输入路径从 `fit.py` 挪到输入层模块。

建议做法：

1. 新建 `input_matrix.py`。
2. 实现 `build_efa_input_matrix(data, config)`。
3. 第一版只复刻当前默认行为：默认 Pearson 相关 + 当前 pandas 缺失值处理 + stabilize。
4. 保证 `fit_efa()` 对外行为不变。

#### 第二步：加入 `missing_strategy`

目标：在不改 extraction/rotation 的前提下，先支持缺失处理切换。

建议做法：

1. 在 `EFAConfig` 中新增 `missing_strategy`。
2. 支持至少：`dropna`、`pairwise`。
3. 为 `pairwise` 输出非正定/有效样本量不足 warning。

当前进展：该步骤已完成首版，后续重点转为补更细的 warning 与正定性修正策略。

#### 第三步：加入 `correlation_method`

目标：把相关矩阵类型从固定 Pearson 改成可配置入口。

建议做法：

1. 在 `EFAConfig` 中新增 `correlation_method`。
2. 第一批先支持：`pearson`、`spearman`。
3. 后续再接 `polychoric`。

当前进展：该步骤已完成首版，并已在统一入口上接入 `polychoric`。

#### 第三步补充：建立 recommendation / `variable_types` 设计

目标：为后续 `polychoric`、`tetrachoric` 和 `auto` 模式打基础，但暂不引入不可控隐式行为。

建议做法：

1. 允许未来在 `EFAConfig` 中加入可选的 `variable_types`；
2. 若未显式提供，则根据唯一值数量、数据类型和分布特征给出 recommendation；
3. recommendation 先写入 warning / metadata，而不是偷偷替换用户配置；
4. 等 recommendation 足够稳定后，再考虑 `correlation_method="auto"`。

当前进展：该步骤已开始首版实现——`variable_types` 已进入 `EFAConfig`，warning recommendation 已在输入层接线，后续重点是补更稳定的识别规则与 metadata 输出。

#### 第四步：实现 `polychoric`

目标：在已经成型的输入层上添加 ordinal 专用相关矩阵。

建议做法：

1. 明确 ordinal 变量输入契约；
2. 先做首版 `polychoric` 估计；
3. 加强数值稳定化与失败 warning；
4. 补针对 Likert 场景的测试。

说明：`polychoric` 不建议直接塞进 extraction，而应继续作为输入矩阵层的一种 `correlation_method` 实现。

当前进展：该步骤已完成第一版——当前已支持在输入层通过 `correlation_method="polychoric"` 构造 ordinal 相关矩阵，并在非 ordinal 输入上给出明确错误；后续重点转为优化估计稳定性、扩展 mixed-type 场景与补 metadata。

#### 第五步：让 workflow 与 ESEM 复用

目标：不要让输入层只服务 `fit_efa()`，而是让后续 workflow 也能共用。

建议做法：

1. 让 `run_efa_workflow()` 也走统一输入层；
2. 后续为 ESEM 的 `efa_seeded` 候选复用这套矩阵准备逻辑。

### 本阶段的完成定义（DoD）

1. `fit_efa()` 仍保持公开 API 稳定。
2. 输入矩阵构造不再直接写死在 `fit.py`。
3. `pairwise` 能正常运行并有明确 warning。
4. 至少补齐 `dropna` vs `pairwise` 的测试。
5. `pearson` / `spearman` 已能通过统一入口切换。
6. 为后续 `polychoric`、数据类型 recommendation 和 `auto` 模式留出清晰扩展位置。

## 4. 提取方法（Extraction）

## 4.1 `minres`

### 核心逻辑 / 计算方式

`minres`（minimum residual）通过最小化样本相关矩阵与模型重建相关矩阵之间的非对角残差平方和来估计载荷。

简化理解：

$$
\min \sum_{i \ne j} (r_{ij} - \hat r_{ij})^2
$$

其中：

- $r_{ij}$ 是观测相关矩阵元素；
- $\hat r_{ij}$ 是由载荷与唯一性重建得到的模型相关矩阵元素。

它关注的是“让模型重建后的相关结构尽可能逼近原始相关结构”。

### 作用

- 是经典 EFA 提取法；
- 通常比 `pca` 更符合因子分析的目标；
- 适合做实际心理测量分析。

### 适用领域

- 心理测量
- 教育测量
- 问卷结构探索
- 社会科学量表初步结构发现

### 不应使用或需谨慎的情况

- 极小样本、极不稳定相关矩阵时要谨慎；
- 如果用户真正想做的是降维而不是潜变量建模，`pca` 更直接；
- 若相关矩阵严重病态，数值优化可能不稳定。

### 对 `psysem` 的价值

- 应作为新增提取法的第一优先级；
- 可与现有 `EFAConfig.extraction` 直接对接；
- 能提高 `run_efa_workflow()` 的分析可信度。

## 4.2 `ml`

### 核心逻辑 / 计算方式

最大似然 EFA 假设观测变量服从多元正态分布，寻找一组参数，使模型协方差矩阵在似然意义下最能解释样本协方差矩阵。

简化目标可写为最小化：

$$
F_{ML}(\Sigma, S) = \log |\Sigma| + \mathrm{tr}(S\Sigma^{-1}) - \log |S| - p
$$

其中：

- $S$ 是样本协方差/相关矩阵；
- $\Sigma$ 是模型 implied 协方差矩阵；
- $p$ 是变量个数。

### 作用

- 更容易衔接统计检验、信息准则和推断；
- 适合与后续 SEM/ESEM 估计逻辑靠近。

### 适用领域

- 正态性较好的连续变量数据；
- 需要信息准则、卡方类比较或更严格推断的研究。

### 不应使用或需谨慎的情况

- 明显偏离正态的 ordinal 数据；
- 样本过小、协方差矩阵不稳定；
- 如果项目当前还没有稳健 ML 和充分的边界处理，初期实现要明确为实验性。

### 对 `psysem` 的价值

- 对后续 ESEM/SEM 融合非常重要；
- 可支持更丰富的因子数选择方法，如基于信息准则的比较。

---

## 4.3 `uls`

### 核心逻辑 / 计算方式

`ULS`（unweighted least squares）最小化观测与模型矩阵残差的平方和，但不使用加权矩阵。

$$
\min \sum_{i,j} (s_{ij} - \hat\sigma_{ij})^2
$$

### 作用

- 形式直观；
- 可作为 ML 之外的替代方案。

### 适用领域

- 想要相对简单的最小二乘型提取；
- 作为方法扩展与对照实现。

### 不应使用或需谨慎的情况

- 若需要更标准的统计推断，`ml` 更合适；
- 若相关矩阵质量较差，结果可能不够稳。

### 对 `psysem` 的价值

- 可作为 P2 扩展；
- 不应优先于 `minres` 和 `ml`。

---

## 4.4 `gls`

### 核心逻辑 / 计算方式

`GLS`（generalized least squares）在最小化残差时引入协方差结构相关的权重矩阵，使某些残差被更强地惩罚。

### 作用

- 理论上比普通最小二乘更精细；
- 可作为高阶扩展。

### 适用领域

- 有较严格统计建模需求；
- 已具备稳定协方差处理与数值优化基础的实现环境。

### 不应使用或需谨慎的情况

- 早期原型阶段；
- 样本量不足、矩阵质量不稳定时。

### 对 `psysem` 的价值

- 价值存在，但当前优先级不高。

---

## 4.5 `pca`（当前已支持）

### 核心逻辑 / 计算方式

PCA 并不区分共同方差与唯一方差，而是直接对协方差/相关矩阵做特征分解，保留前几个主成分。

### 作用

- 做降维非常直接；
- 数值实现简单；
- 可作为探索性基线方法。

### 适用领域

- 降维；
- 粗略探索结构；
- 作为 EFA 结果的对照参照。

### 不应使用或需谨慎的情况

- 若研究目标是潜变量测量模型，而不是单纯降维；
- 若需要严格解释共同因子结构。

### 对 `psysem` 的定位

- 适合作为基础方法保留；
- 但不应被视为心理测量 EFA 的最终核心方法。

---

## 4.6 `paf`（当前已支持）

### 核心逻辑 / 计算方式

PAF（principal axis factoring）先估计共同度，再对修正后的相关矩阵做迭代分解，逐步逼近共同因子结构。

### 作用

- 是非常常见的传统因子提取法；
- 与心理测量语境较匹配。

### 适用领域

- 连续变量量表结构探索；
- 与 `varimax` 或斜交旋转结合使用。

### 不应使用或需谨慎的情况

- 数据极其稀疏、相关矩阵很差时；
- 若需要更严密的统计推断，可能不如 `ml`。

### 对 `psysem` 的定位

- 当前默认提取法是合理的；
- 后续应与 `minres`、`ml` 形成三核心方案。

---

## 5. 旋转方法（Rotation）

## 5.1 `promax`

### 核心逻辑 / 计算方式

`promax` 通常先做一次正交旋转（如 varimax），再将载荷矩阵进行幂变换，形成更稀疏的目标结构，并允许因子相关。

### 作用

- 是非常常见的斜交旋转；
- 更符合心理测量中因子彼此相关的现实。

### 适用领域

- 情绪、人格、教育测量等因子相关常见的场景；
- 需要较清晰简单结构，又不想强制因子独立。

### 不应使用或需谨慎的情况

- 如果研究明确要求正交因子；
- 在样本很小、载荷结构极不稳定时，斜交结果可能更难解释。

### 对 `psysem` 的价值

- 应作为 P0 优先新增；
- 能显著提升项目对心理学用户的吸引力。

---

## 5.2 `oblimin`

### 核心逻辑 / 计算方式

`oblimin` 通过优化旋转准则，使载荷矩阵更接近简单结构，同时允许因子之间相关。

### 作用

- 是最经典的斜交旋转之一；
- 在研究型分析中很常用。

### 适用领域

- 因子相关预期明确的量表开发与结构探索；
- 心理测量、教育测量、社会科学。

### 不应使用或需谨慎的情况

- 需要因子彼此独立的理论场景；
- 若用户不熟悉斜交旋转，解释时要明确区分“载荷”和“因子相关”。

### 对 `psysem` 的价值

- 与 `promax` 一起，应成为第一批旋转扩展。

---

## 5.3 `geomin`

### 核心逻辑 / 计算方式

`geomin` 倾向于让每个题项的大多数载荷尽可能小，仅保留少数较大的载荷，因此对“近似简单结构”很友好。

其思想不是硬性把非目标载荷压成精确零，而是倾向于让它们足够小。

### 作用

- 对 ESEM 很重要；
- 能自然连接“允许小交叉载荷”的模型思路。

### 适用领域

- ESEM 过渡路径；
- 因子间相关且允许小交叉载荷的心理测量场景。

### 不应使用或需谨慎的情况

- 如果用户希望的是极强的简单结构、完全接近传统 CFA 风格解释；
- 如果实现中数值优化和收敛控制还不充分，要明确实验性。

### 对 `psysem` 的价值

- 是通向 ESEM 的关键方法；
- 已完成首版实现，并纳入当前 EFA 旋转选项；
- 下一步重点应放在数值稳定性、多起点策略与后续 ESEM 路线整合。

---

## 5.4 `target rotation`

### 核心逻辑 / 计算方式

目标旋转不是完全自由地寻找简单结构，而是根据给定目标矩阵，让某些位置趋近于大载荷、另一些位置趋近于零或近零。

### 作用

- 理论引导很强；
- 与 `target pattern`、ESEM workflow 直接相关。

### 适用领域

- 已有理论结构预期；
- 希望保留探索性灵活性，但不完全放任旋转自由。

### 不应使用或需谨慎的情况

- 理论模板本身不可靠；
- 用户把它误当成“自动证明理论正确”的工具。

### 对 `psysem` 的价值

- 对未来 [docs/esem-modular-workflow.zh-CN.md](esem-modular-workflow.zh-CN.md) 中的 `target_pattern` 路线非常关键；
- 已完成首版接入，支持基于目标矩阵的 EFA 旋转；
- 已补充目标权重控制，可区分强约束、弱引导与自由位置；
- 下一步应继续补充更完整的目标模式语法与 ESEM block 集成。

---

## 5.5 `quartimin`

### 核心逻辑 / 计算方式

`quartimin` 是一种斜交旋转准则，目标也是促进简单结构，但优化形式和 `oblimin` 不同。

### 作用

- 可作为 `oblimin` 的扩展或对照；
- 适合补充旋转选项。

### 适用领域

- 已有一套完整斜交旋转实现后，作为扩展提供给高级用户。

### 不应使用或需谨慎的情况

- 在项目还未形成稳定斜交旋转基础设施前，不应优先实现。

### 对 `psysem` 的价值

- 有用，但属于 P2。

---

## 5.6 `equamax`

### 核心逻辑 / 计算方式

`equamax` 试图在变量简单结构和因子简单结构之间做折中，是一种正交旋转。

### 作用

- 可作为 `varimax` 的补充；
- 帮助用户比较不同正交旋转结果。

### 适用领域

- 明确希望保留因子独立假设的场景。

### 不应使用或需谨慎的情况

- 心理测量里因子相关常见，不应机械优先于斜交旋转。

### 对 `psysem` 的价值

- 可加，但优先级不高。

---

## 5.7 `varimax`（当前已支持）

### 核心逻辑 / 计算方式

`varimax` 通过最大化各因子载荷平方的方差，让每个因子上出现少数大载荷、更多小载荷，且保持因子正交。

### 作用

- 最常见的正交旋转；
- 解释直观；
- 实现成熟稳定。

### 适用领域

- 需要快速解释结果；
- 暂时接受“因子不相关”近似假设。

### 不应使用或需谨慎的情况

- 若理论上因子应相关；
- 若强行用正交旋转掩盖本来存在的因子相关。

### 对 `psysem` 的定位

- 作为当前默认旋转合理；
- 但后续应让斜交旋转成为更常用选项。

---

## 5.8 `none`（当前已支持）

### 核心逻辑 / 计算方式

不做旋转，直接使用提取后载荷。

### 作用

- 便于调试与方法对照；
- 可观察原始提取结果。

### 适用领域

- 算法调试；
- 教学与方法比较。

### 不应使用或需谨慎的情况

- 真实解释场景下通常不宜作为最终报告结果。

### 对 `psysem` 的定位

- 应保留，但不是主要用户工作流的首选。

---

## 6. 因子数建议方法（Factor Retention）

## 6.1 `parallel analysis`（当前已支持）

### 核心逻辑 / 计算方式

将真实数据的特征值与随机数据生成的特征值阈值进行比较，保留那些明显高于随机基线的因子。

### 作用

- 在实践中非常常用；
- 通常比单纯 Kaiser 更稳。

### 适用领域

- 大多数 EFA 因子数建议场景。

### 不应使用或需谨慎的情况

- 样本极小或变量质量很差时，结果仍可能波动；
- 若随机模拟次数太少，稳定性会下降。

### 对 `psysem` 的定位

- 应继续作为核心方法保留。

---

## 6.2 `MAP`（当前已支持）

### 核心逻辑 / 计算方式

通过逐步提取因子后观察部分相关残差的平均平方值，选择残差最小的因子数。

### 作用

- 与 PA 形成互补；
- 对“还剩多少系统结构没解释完”很有帮助。

### 适用领域

- 需要多方法联合判断的场景。

### 不应使用或需谨慎的情况

- 在结构很复杂或样本质量差时，曲线可能不够稳定。

### 对 `psysem` 的定位

- 应保留并继续强化可解释输出。

---

## 6.3 `Kaiser`（当前已支持）

### 核心逻辑 / 计算方式

保留特征值大于 1 的因子。

### 作用

- 简单直观；
- 计算代价低。

### 适用领域

- 粗略参考；
- 作为多方法共识中的一个投票来源。

### 不应使用或需谨慎的情况

- 绝不建议单独作为唯一依据；
- 变量数量和相关结构变化时可能偏差较大。

### 对 `psysem` 的定位

- 保留，但应始终作为辅助方法。

---

## 6.4 `scree`（当前已支持）

### 核心逻辑 / 计算方式

查看特征值曲线的拐点，将拐点前的因子视为应保留的主结构。

### 作用

- 很直观；
- 对人工判断有帮助。

### 适用领域

- 教学、探索、与其他方法对照。

### 不应使用或需谨慎的情况

- 拐点不明显时，主观性较强；
- 若自动 elbow 算法过于简单，结果容易受噪声影响。

### 对 `psysem` 的定位

- 建议后续继续增强自动 elbow 算法。

---

## 6.5 `VSS`

### 核心逻辑 / 计算方式

Very Simple Structure 通过比较不同因子数下“简化载荷结构”对相关矩阵的拟合程度，寻找最简单且解释性较好的因子数。

### 作用

- 很适合和简单结构目标相结合；
- 对解释型因子分析很有价值。

### 适用领域

- 量表开发；
- 强调结构清晰和解释性的场景。

### 不应使用或需谨慎的情况

- 当真实结构本来就允许较多交叉载荷时，VSS 可能偏向更简单但不一定更真实的结构。

### 对 `psysem` 的价值

- 应作为 P1 添加到因子数建议体系中。

---

## 6.6 `Hull`

### 核心逻辑 / 计算方式

Hull 方法试图在模型拟合与复杂度之间寻找最优折中点。

### 作用

- 适合做“复杂度惩罚”意义下的因子数选择；
- 能作为 PA/MAP 的补充。

### 适用领域

- 想要更系统地平衡拟合与简约性。

### 不应使用或需谨慎的情况

- 若当前项目对拟合指标和复杂度度量尚未稳定，过早引入会增加调试难度。

### 对 `psysem` 的价值

- 适合 P2。

---

## 6.7 `EKC`

### 核心逻辑 / 计算方式

Empirical Kaiser Criterion 对传统 Kaiser 做经验修正，希望减少其过度保留或不足保留的问题。

### 作用

- 可视为 Kaiser 的改良版。

### 适用领域

- 需要保留一个简单、可快速解释的方法，同时希望比传统 Kaiser 稳一些。

### 不应使用或需谨慎的情况

- 不应取代 PA/MAP；
- 若用户误把它当成金标准，会造成过度自信。

### 对 `psysem` 的价值

- 可作为补充，但非优先。

---

## 6.8 `acceleration factor`

### 核心逻辑 / 计算方式

通过特征值曲线的二阶变化寻找最明显拐点，是对 scree 自动化的一种补强。

### 作用

- 提高 scree 自动建议的客观性。

### 适用领域

- 想减少纯人工看图判断。

### 不应使用或需谨慎的情况

- 曲线噪声大时，自动拐点也可能不稳。

### 对 `psysem` 的价值

- 适合作为 `scree` 的内部增强，而不是独立主方法。

---

## 7. 输入预处理与数据处理方法

## 7.1 `pairwise` 缺失处理

### 核心逻辑 / 计算方式

不同变量对的相关系数使用该变量对可用的全部样本，而不是整行删除。

### 作用

- 比 `dropna` 更充分利用数据；
- 在问卷存在少量缺失时常见。

### 适用领域

- 缺失较少、变量较多的调查数据；
- 不希望 listwise deletion 造成样本量骤降。

### 不应使用或需谨慎的情况

- 缺失模式复杂时，pairwise 得到的相关矩阵可能不正定；
- 若后续算法依赖稳定正定矩阵，需要额外修正。

### 对 `psysem` 的价值

- 是缺失处理扩展的第一优先级。

---

## 7.2 `mean / median imputation`

### 核心逻辑 / 计算方式

使用变量均值或中位数填补缺失。

### 作用

- 实现简单；
- 可在某些教学或极简基线场景中使用。

### 适用领域

- 演示、对照实验、极简预处理。

### 不应使用或需谨慎的情况

- 正式研究分析一般不推荐；
- 会低估方差、扭曲相关结构。

### 对 `psysem` 的价值

- 可以有，但不应默认推荐。

---

## 7.3 `EM / MI` 级别缺失处理

### 核心逻辑 / 计算方式

- `EM`：通过期望最大化迭代估计缺失部分；
- `MI`：进行多重插补，综合多次插补结果。

### 作用

- 比简单删除和均值插补更严谨；
- 对正式研究更合适。

### 适用领域

- 样本重要、缺失不可忽略的研究场景；
- 更接近正式发表标准的分析流程。

### 不应使用或需谨慎的情况

- 当前项目还在 alpha 阶段，不适合太早引入复杂缺失框架；
- 没有完整诊断和文档时，容易被误用。

### 对 `psysem` 的价值

- 长期重要，但不宜近期优先。

---

## 8. 相关矩阵类型

## 8.1 `pearson`（当前默认思路）

### 核心逻辑 / 计算方式

基于连续变量线性关系计算相关。

### 作用

- 最常见；
- 适合连续变量。

### 适用领域

- 近似连续、近似正态数据。

### 不应使用或需谨慎的情况

- 明显 ordinal 的 Likert 数据；
- 存在严重偏态时。

### 对 `psysem` 的定位

- 当前可继续作为默认。

---

## 8.2 `spearman`

### 核心逻辑 / 计算方式

基于秩而非原始值计算相关，更稳健地反映单调关系。

### 作用

- 对非正态和异常值更稳健；
- 可作为轻量扩展。

### 适用领域

- 非正态分布；
- 顺序型但暂时不做 polychoric 的数据。

### 不应使用或需谨慎的情况

- 若后续方法理论上明确依赖 Pearson/协方差结构。

### 对 `psysem` 的价值

- 可作为较低成本的输入扩展。

---

## 8.3 `polychoric`

### 核心逻辑 / 计算方式

假设 ordinal 观测变量来自潜在连续正态变量的阈值切分，估计潜在连续变量之间的相关。

### 作用

- 对 Likert 题尤其重要；
- 是心理测量 ordinal 场景的关键方法。

### 适用领域

- Likert 量表；
- 有序分类数据；
- 后续 ESEM/SEM 想认真处理 ordinal 数据时。

### 不应使用或需谨慎的情况

- 样本太小、类别过少且分布极偏时，估计可能不稳定；
- 若实现不成熟，数值问题会很多。

### 对 `psysem` 的价值

- 应作为 P1 优先功能；
- 是从“基础 EFA 工具”走向“心理测量包”的关键一步。

---

## 8.4 `tetrachoric`

### 核心逻辑 / 计算方式

是 `polychoric` 在二分类变量上的特例，估计潜在连续变量之间的相关。

### 作用

- 用于二分类题项。

### 适用领域

- 是/否题、二元反应题。

### 不应使用或需谨慎的情况

- 样本不足或比例极端不平衡时。

### 对 `psysem` 的价值

- 重要，但优先级略低于更通用的 `polychoric`。

## 9. 总结建议

## 已完成的第一批关键扩展

1. `minres`
2. `promax`
3. `oblimin`
4. `geomin`

这组最小投入、最大收益的扩展已经完成，并为后续 ESEM 路线打下了基础。

## 当前最优先的第二阶段能力

1. 输入预处理层
2. `pairwise`
3. `spearman`
4. `polychoric`
5. `vss`

这批方法能直接把 `psysem` 从“当前基础 EFA 工作流”往“更专业心理测量工具”推进。

> 更新：`ml` 已完成首版实现，因此当前最优先的下一步应转为“输入预处理层”，再在这层上依次接入 `pairwise`、`spearman`、`polychoric` 与 `vss`。

## 当前不建议优先做的

1. `mean/median imputation` 作为正式分析默认选项
2. 单独依赖 `Kaiser` 作为因子数决策
3. 在没有稳定数值基础前就优先做 `gls`
4. 在没有明确理论模板前就推动复杂 `target rotation`

### 文档侧建议

README 或参数文档中应逐步明确：

1. 提取方法与旋转方法的差别；
2. 何时用正交、何时用斜交；
3. 何时用 Pearson，何时考虑 polychoric；
4. 因子数建议方法不能依赖单一规则。
